# TriCNES 20260521 vs 20260410 — 模擬器實作差異（修正參考）

**日期**: 2026-05-21
**比較對象**:
- 新版: `ref/TriCNES-main-20260521/`（AC 作者 100thCoin 最新 commit）
- 舊版: `ref/TriCNES-main-20260410/`
**目的**: TriCNES 是 AccuracyCoin 測試 ROM 作者自己的模擬器（AC 滿分基準）。對照新舊版找出他改了什麼，作為我們對齊 AC 20260521 新測試（特別是新增的 `Internal Data Bus`）的修正參考。相關：[[AccuracyCoin_20260521_diff_and_result]]。

## 0. 範圍與兩個 caveat

實際改動的原始檔（排除 bin/obj/packages/.vs）：

## 1. 🎯 重點：`$4015` 讀取改用持久 `internalBus` 欄位

這正是對應 AC 20260521 新增的 `Internal Data Bus` 測試（我們目前 fail 在它的 Test 2 / error code 2）。

### 舊版（20260410，`Emulator.cs` 約 9080）
```csharp
byte InternalBus = dataBus;          // ← local 變數，每次讀 $4015 都從外部 dataBus 重新 seed
InternalBus &= 0x20;
InternalBus |= (byte)(APU_Status_DMCInterrupt ? 0x80 : 0);
...（length counter 等 status bits）
return InternalBus;                  // reading from $4015 can not affect the databus
```

### 新版（20260521，`Emulator.cs:9254-9274` + 欄位 `:496`）
```csharp
public byte internalBus = 0;         // 新欄位：The Data Bus (internal to address $4015)
...
if (Reg == 0x15) {
    internalBus &= 0x20;             // ← 用持久欄位，bit5 沿用上一次的 internal bus，「不」從 dataBus 重 seed
    internalBus |= (byte)(APU_Status_DMCInterrupt ? 0x80 : 0);
    ...（同樣的 status bits）
    Clearing_APU_FrameInterrupt = true;
    return internalBus;              // ← 直接 return，「跳過」函式尾端的 internalBus = dataBus
}
...
internalBus = dataBus;               // :9305 一般 read 才會把 internal 同步到 external
return dataBus;
```

### 差別與為什麼

| | 舊 | 新 |
|---|---|---|
| `$4015` bit5 來源 | local `InternalBus = dataBus`（**從外部 bus 重 seed**）| 持久欄位 `internalBus`（**不**從 dataBus 重 seed）|
| 一般 read/write | — | 函式尾 `internalBus = dataBus` 讓兩者同步 |
| `$4015` read | — | 提前 `return`，**不**同步、**不**更新 dataBus |

新測試的場景：一個 DMC DMA sample fetch 把 `$60`（bit5=1）放上**外部** `dataBus`，緊接著 `LDA $4015`。
- **舊版**會 `InternalBus = dataBus` → 把 DMA 的 `$60` 撈進來 → bit5=1 → **fail**（所以作者才改）。
- **新版** `internalBus` 是獨立欄位，DMC DMA 的外部 fetch 不會更新它 → bit5 維持舊值 0 → **pass**。

### 對應我們的修法（AprNes）
我們現在 `APU.cs:934` 是單一 `cpubus`：
```csharp
status |= (byte)(cpubus & 0x20); // bit 5 is open bus (CPU data bus)
```
照 TriCNES 新版的模型改：
1. 新增獨立欄位（例如 `internalBus`），跟既有 `cpubus`（=外部 data bus）分離。
2. 一般 CPU read/write：`internalBus = cpubus`（兩者同步）——對應 TriCNES `:9305`。
3. **DMC DMA sample fetch**：只更新 `cpubus`（外部），**不**碰 `internalBus`。這是關鍵：我們現在 DMC DMA 會寫 `cpubus`，導致汙染。
4. `$4015` 讀取：bit5 取自 `internalBus`，且不更新 `internalBus`、不更新 `cpubus`（`$4015` 讀不改 external bus，我們 `CPU.cs:82` 的 `if (addr != 0x4015) cpubus = val;` 已處理一半）。
5. Test 3（反向）也要一起對：DMC DMA 後從 open bus 讀，期望保留 external 的舊值。

> 符合「以 TriCNES 為唯一準則、禁止自創補償」原則——直接照搬這個 internal/external 雙 latch 模型。

## 2. Sprite shift register in-range 清除的 scope 調整

`Emulator.cs` 舊 2934-2989 / 新 3118-3170。清除 `PPU_SpriteShiftRegisterL/H[OAM2Address/4] = 0`（object 不在範圍時清掉 shift register）的 in-range check 被移進不同的 brace scope。

這對應 AC 20260521 那批 sprite 測試的期望值修正：
- **Stale Sprite Shift Regs**：error code 3 與 5 情境對調
- **Sprites On Scanline 0**：error code 從 3 個擴充成 6 個

→ 我們實測這批 sprite 測試**全過**，代表既有行為已對齊；這段 TriCNES 改動主要是讓他自己的 in-range 清除時機與新測試一致。**我們目前不需要動**，但若日後 sprite shift register 有回歸，這裡是對照點。

## 3. FDS DiskDrive 重寫（與 NES 精度無關）

`Emulator.cs` 新增整個 `DiskDrive` class（`RamAdapterState` 狀態機 RUNNING/INSERTING/SPINUP/RESET/IDLE、`Clock()`、disk gap 偵測等），搭配 `mappers/Mapper_FDS.cs` +99/−3、新增 `FDS_Get4025()` 虛擬方法。

這是 Famicom Disk System 磁碟機時序的重寫，跟 NES cartridge 的 CPU/PPU/APU 精度無關。我們的 FDS 是另一套實作（`NesCore/FDS.cs`），**不需要**參考這段。純粹記錄「+225 行裡有一大半是 FDS，不是 NES 核心改動」。

---

## 4. 雜項：dead code 清理

`Emulator.cs` 舊 1811-1818 移除了幾個空的 debug if-block：
```csharp
if(PPU_v == 0x1F00) { }   // 空
if (PPU_v == 0x1EFF) { }  // 空
```
以及一處重複的 `PPU_v += (PPUControlIncrementMode32 ? 32 : 1)`。純清理，無行為影響。

---

## 5. 結論

對我們有用的就**一條**：第 1 節的 `$4015` internal/external data bus 拆分。這直接是我們 fail 的 `Internal Data Bus` Test 2（error code 2）的標準答案，照 TriCNES 新版的 `internalBus` 欄位模型改 `APU.cs:apu_r_4015()` + DMC DMA fetch 路徑即可。其餘（sprite scope、FDS、dead code）不影響我們目前的 138/139。

> **✅ 已照此修復 (2026-05-22)** — 見 [bugfix/2026-05-22_AC_InternalDataBus_DualDataBus](../bugfix/2026-05-22_AC_InternalDataBus_DualDataBus.md)。實作上採「DMA fetch 不更新 internalBus」的模型（與 TriCNES 把 DMA 也走 Fetch 略有不同，但對 P20 Test 2/3 行為等價且實測通過）。139/139 達成，blargg 184/184 無回歸。
