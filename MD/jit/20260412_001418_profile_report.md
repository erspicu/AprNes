## 6. Hot Path Inline 交叉分析

**所有 Top 20 熱點方法都不是被 inline 的** — 它們是獨立的 JIT'd 方法：

| Excl% | Inlined? | Method |
|-------|----------|--------|
| 30.6% | standalone | `ppu_step_new()` |
| 17.1% | standalone | `run()` |
| 11.6% | standalone | `PpuPhase4_SpriteEvalAndInit()` |
| 11.5% | standalone | `PPU_DATA_StateMachine()` |
| 9.5% | standalone | `PPU_DATA_StateMachine_Half()` |
| 7.3% | standalone | `apu_step()` |
| 1.7% | standalone | `cpu_step_one_cycle()` |
| 1.5% | standalone | `processLenCtrReloadNonHalf()` |
| 1.5% | standalone | `ApuFrameCounterStep()` |

這是合理的 — 這些方法的 IL size 都太大，JIT 不會嘗試 inline 它們。

**被成功 inline 的重要方法**：`MasterClockTick` (4x), `ppu_half_step_new` (4x), `PpuBusRead` (12x), `CXinc` (4x) — 這些高頻小方法的 inline 對效能有正面影響。

## 7. 優化建議

### 最高優先級
1. **`ppu_step_new` (30.6%)** — 最大熱點。檢查是否有分支可以提前退出、條件判斷可以重新排序
2. **SR Latch SM (21.3%)** — 考慮合併三個 SM 方法或簡化 latch pipeline 邏輯
3. **`run()` (17.1%)** — opcode switch 本身。考慮 function pointer table 取代 switch

### 中優先級
4. **`PpuPhase4_SpriteEvalAndInit` (11.6%)** — sprite eval FSM 簡化
5. **`apu_step` (7.3%)** — 考慮降頻或批次處理

### 低優先級
6. `cpu_step_one_cycle` / `ApuFrameCounterStep` / `processLenCtrReloadNonHalf` — 各 ~1.5%
