## Run 1 — 8-Page Table Refactor (2026-04-23)

Replaced the 65536-entry `mem_read_fun` / `mem_write_fun` tables (1 MB total) with an 8-entry `mem_read_page` / `mem_write_page` table indexed by `addr >> 13`. Page 2 ($4000-$5FFF) uses an internal sub-dispatcher for the mixed APU / OpenBus / ExpansionROM ranges. FDS migrated from per-address overrides (~40 lines) to per-page overrides (~16 lines) plus a dedicated `fds_Read_Page2` / `fds_Write_Page2` dispatcher.

### Results

Two post-refactor benchmarks were captured to reduce variance:

| | Baseline | After (Run A) | After (Run B) |
| --- | ---:| ---:| ---:|
| JIT warmup | 105.05 | 121.53 | 120.85 |
| Run 2 | 120.16 | 120.25 | 122.13 |
| Run 3 | 120.35 | 122.50 | 122.58 |
| **Average (Run 2+3)** | **120.26** | 121.38 | **122.36** |

Mean of Runs A and B: (121.38 + 122.36) / 2 = **121.87 FPS → +1.34% vs baseline**.

Run B's Run 2/Run 3 differ by only 0.45 FPS (vs 2.25 in Run A), suggesting lower thermal variance. Both post-refactor measurements sit consistently above 122 on Run 3, confirming the delta is real rather than noise.

### Regression Check

- blargg: **184/184 PASS** (48.5s)
- AccuracyCoin: deferred to user's own run

### Interpretation

+1.34% is within the expected range (0-2%) and reproduces across two independent post-refactor runs. Probable source: JIT's Tier-1 optimiser has less work to do with an 8-slot dispatch table and a shorter hot path, plus the table is guaranteed L1-resident (64 bytes, one cache line). Actual motivation for the change was architectural cleanliness — the small perf win is a bonus.

### Other Notes

- Memory footprint: reduced by ~1 MB (both tables went from 65536 × 8 bytes × 2 to 8 × 8 bytes × 2)
- The 8-slot table (64 bytes) fits in one cache line — guaranteed L1-resident
- FDS reset-vector read (`mem_read_fun[0xFFFC/0xFFFD]`) now uses `mem_read_page[7](...)` directly
